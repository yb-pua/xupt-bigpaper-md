## 3. 技术约束（与专利一致，不可偏离）

| 项 | 必须实现 |
|---|---|
| 特征提取 | InsightFace buffalo_l 512 维（主）；dlib 128 维（对比档）；两者可切换 |
| 预处理 | Min-Max 归一化到 [0,1]（专利公式） |
| 稳定比特 | 多数投票（众数）+ 稳定性评分，**阈值 0.8**，形成稳定比特序列 |
| 密钥生成 | bio_key = **SM3**(稳定序列) → 256 bit |
| 纠错码 | **主码 RS(255,191,t=32 字节)**（reedsolo 库）；重复码、BCH 为对比项 |
| 辅助数据 | σ 不含原始特征信息；只存 σ + key_hash=SM3(bio_key)（非存储式，模板即弃） |
| DID | 格式 `didsm9:<user_id>:<SM3 哈希>`，冲突自动重试 |
| KGC | 基于 DID 派生 SM9 私钥；**KGC 运行于模拟 TEE**（独立进程 + 主密钥不进日志 + 派生审计日志），无 SGX 时明确标注"模拟 TEE" |
| SM9 | **gmalg 库（主）**：SM9 签名/验签/密钥派生全部走 gmalg（gmssl Python 版不支持 SM9，无需安装）；gmalg 亦提供 SM3/SM4（全链路一个库）；若 gmalg 某接口不可用 → 模拟实现并**在 README 与代码注释标注"SM9 模拟"**；gmssl 仅作 SM3/SM4 可选备选（backend 可切换，非必需） |
| Kerberos | 注册（SM9 签名 user_id+DID+时间戳）→ AS-REQ **前置 SM9 验签替代口令哈希** → TGT→TGS→ST 标准流程；**时间戳窗口 30 min**（NTP 语义，可配置）；票据载荷加密 **SM4**（保留标准票据格式） |
| 熔断 | 连续失败 **3 次** → is_blocked=true → 删除全部会话与票据 → 强制完整重注册恢复 |
| 哈希 | 全部 **SM3**（bio_key/key_hash/DID/完整性），禁止 SHA-256/BLAKE2b |
| 随机性 | 全部固定 seed（全局 SEED 常量，README 记录） |
| 匿名 | 代码、注释、README 不得出现作者/学校等身份信息 |

## 5.1 接口预留（方向二/三复用，必须实现）

`kerberos_enhanced.py` 的票据接口必须抽象，供方向二（P2PVPN 中继）、方向三（MCP 服务端）复用验签逻辑：

```python
class Ticket:
    fields: realm, principal(DID), service, claims(dict), times(start/end),
            nonce, payload_enc(SM4), sig(SM9)

# 签发：KDC 侧
issue_ticket(principal, service, claims, ttl_minutes) -> Ticket
# 验证：任意验证方（AS/TGS/中继/MCP 服务端）
verify_ticket(ticket, expected_service, claims_checker=None) -> (valid: bool, reason: str)
# claims_checker: 回调校验 claims 字段（方向二校验 NetPerm 组网权限，
#                 方向三校验 ST_data 权限集合）；None 时仅验签+时效
```

- **票据结构**：JSON 载荷（含 claims 字典，预留扩展字段）+ SM4 加密 + SM9 签名（KDC 主密钥派生）；
- **验证方无关**：验签逻辑只依赖 SM9 公钥体系，不依赖方向一角色——方向二中继、方向三 MCP 服务端调用同一 `verify_ticket`；
- **验收**：方向一实验验证 TGT/ST 全流程可用；`claims_checker` 回调被正确调用（可在单测中注入假 claims 验证）。

## 6. 实验脚本设计（experiments/，各自独立可跑 + run_all 汇总）

### exp_a1_recoverability.py（A1：密钥可恢复性）
- 输入：5 张档 423 人（主）；8/10 张档（对比）；跨条件双样本；异人 ≥5000 对
- 流程：录入（前 k 张投票+gen）→ 验证（余张/扰动副本 rep）→ 阈值扫描（0-1 步长 0.01）
- 输出 CSV：
  - `expA1_krr_threshold.csv`（threshold, krr, far, frr）
  - `expA1_roc_curve.csv`（fpr, tpr, auc）
  - `expA1_vote_compare.csv`（vote_bucket, n_persons, stable_ratio, krr, far, eer）
  - `expA1_cross_condition.csv`（krr_real 跨条件 / krr_noise 扰动，分档）
  - `expA1_summary.csv`（eer, auc, krr 等汇总）
- 同时输出维度对比：`expA1_dim_compare.csv`（backend, dim, extract_ms, eer, krr）

### exp_a2_noise.py（A2：噪声鲁棒性）
- 输入：同人样本 + 三型扰动强度梯度（高斯 σ、亮度 ±%、仿射角度）
- 输出：`expA2_noise_robustness.csv`（noise_type, intensity, recovery_rate, hamming_dist_mean）

### exp_a3_e2e.py（A3：端到端认证全流程）
- 流程：注册（签名+验签+时间戳）→ 认证（AS-REQ 验签 → TGT）→ TGS → ST → 服务访问；含熔断路径（3 次失败 → blocked → 重注册恢复）
- 输出：`expA3_e2e_results.csv`（success, stage_latency 分解）、`expA3_stage_latency.csv`

### exp_a4_performance.py（A4：三基线性能对比）
- 基线：①口令 Kerberos（口令哈希校验+标准票据）；②国密替换版（SM2/SM4 替换，仅入口算法替换）；③本文（SM9 生物签名）
- 指标：AS-REQ 全流程时延（p50/p90）、各阶段分解（特征提取/投票/RS/SM9 验签/票据签发）、消息尺寸
- 输出：`expA4_performance.csv`、`expA4_message_sizes.csv`

### exp_a5_attacks.py（A5：6 类攻击）
| 用例 | 实现方式 | 输出列 |
|---|---|---|
| A5-1 重放 | 过期 ts（>30min）/重复 nonce 重发 | attempts, blocked, block_rate |
| A5-2 伪造票据 | 随机密钥签名 ST | 同上 |
| A5-3 DID 冒用 | 合法签名+错误 DID 绑定 | 同上 |
| A5-4 泄露恢复 | 仅持 σ+key_hash 尝试恢复特征/密钥 | attack_success_rate（应≈0） |
| A5-5 暴力破解 | 连续错误认证至阈值 | 熔断触发率、恢复流程正确性 |
| A5-6 篡改 | 修改 M 不重签 | 拦截率 |
- 输出：`expA5_attack_results.csv`（attack_type, attempts, blocked, block_rate, note）

### exp_a6_template_compare.py（扩展：非存储式 vs 安全模板）
- 对比方案：A=非存储式（σ+key_hash，本文）；B=BioHashing（随机投影变换模板存储，可撤销）
- 指标：存储内容与大小、EER 保持、撤销实验（换投影密钥后旧模板失效）、隐私攻击面（模板泄露后的恢复成功率）
- 输出：`expA6_template_compare.csv`（scheme, storage_bytes, eer, revoke_ok, leak_recovery_rate）

## 8. 验收标准（全部通过才算完成）

1. `run_all.py` 从空 results 目录一键复现全部 CSV（无手改数据）；
2. 抽查 3 组 CSV 数值与代码逻辑一致（如 KRR=恢复成功/总数）；
3. RS 纠错自测：注入 ≤32 字节错误 → 100% 恢复；>32 字节 → 失败；
4. 熔断自测：连续 3 次失败 → is_blocked；恢复流程重建绑定成功；
5. 时间戳窗口：ts 超过 30min 的请求 100% 拒绝；
6. SM9 模拟模式在 README 与代码头注释显式标注；
7. 匿名检查：`grep -rn "姓名\|学校\|学院" core/ experiments/ README.md` 零命中；
8. 与专利一致性抽查：DID 格式 `didsm9:`、阈值 0.8、RS(255,191,t=32)、30min、3 次熔断——代码常量可查。
