# 实验需求点清单（供代码设计）

> 分工：本文档为需求侧（论文侧）提出的全部实验需求点；代码侧按此设计实现。
> 每个需求点含：目的、功能模块、输入数据、输出指标、验收标准。
> 输出数据统一按第 5 节规约，保证论文可直接取用、可复现。

---

## 0. 总体实验架构

三个研究方向 → 三组实验簇：

```
方案一（身份认证）：生物特征→稳定密钥→SM9签名→Kerberos AS-REQ
  ├─ 实验 A1 密钥可恢复性（KRR/FAR/FRR/EER）
  ├─ 实验 A2 噪声鲁棒性
  ├─ 实验 A3 端到端认证全流程
  ├─ 实验 A4 性能对比（vs 口令Kerberos / 国密替换版）
  └─ 实验 A5 攻击用例（重放/伪造/冒用/泄露）
方案二（安全组网）：设备DID→SM9授权→ST票据→中继验证→SM9密钥协商隧道
  ├─ 实验 B1 组网准入功能（合法/过期/冒用三类节点）
  ├─ 实验 B2 节点规模扩展性（N=10/50/100/200）
  ├─ 实验 B3 隧道与流量整形效果
  └─ 实验 B4 攻击用例（重放ST/伪造授权/DID冒用/恶意中继）
方案三（MCP应用）：双DID→ST_data/ST_net分级授权→双签名链→四步验证
  ├─ 实验 C1 分级授权功能（三类场景跑通）
  ├─ 实验 C2 签名链验证性能（并发与开销）
  ├─ 实验 C3 指令攻击与正确性（正常/篡改/越权/重放）
  └─ 实验 C4 安全属性对比矩阵（vs Kerberos/OAuth直连）
```

## 1. 方案一需求点（SM9 + 生物模糊提取 + Kerberos）

### 1.1 生物特征采集与特征提取
- **目的**：从人脸图像得到固定长度、可分性的数值特征向量。
- **功能**：图像加载 → 人脸检测/对齐 → 特征嵌入（输出 512 维或 128 维向量）。
- **输入**：LFW 数据集（公开）或自采图片；需支持"同一人多张照片"。
- **输出**：每张照片一个特征向量文件（npy 或 CSV）。
- **验收**：同一人不同照片特征余弦相似度显著高于不同人（可区分性可测）。
- **维度对比实验（新增）**：128 维（dlib，专利实施例）vs 512 维（InsightFace）——输出提取耗时、EER、KRR，数据文件 `expA1_dim_compare.csv`（model, dim, extract_ms, eer, krr）。

### 1.2 稳定比特提取
- **目的**：将实值特征向量转为稳定二进制串（密钥材料）。
- **功能**：支持至少两种方法（如随机投影法、量化法）且可配置种子；提供"同人多照片投票"模式（每位置比特取众数，输出投票一致率）。
- **输入**：特征向量 + 方法参数。
- **输出**：比特序列 + 稳定性统计（每比特一致率、稳定比特占比）。
- **验收**：可输出投票一致率随照片数（4/6/8/10）变化曲线所需数据。

### 1.3 模糊提取器（Gen/Rep）
- **目的**：从含噪比特串生成可精确再生的密钥 R 与辅助数据 P。
- **功能**：
  - Gen(w) → (R, P)：随机码字 c → P = w ⊕ Encode(c)，R = SM3(c)（256bit bio_key）；
  - Rep(w′, P) → R′：纠错译码恢复 c → R′；
  - **主纠错码：RS(255,191,t=32字节)**（专利主成果配置）；重复码/BCH 为对比项（纠错码对比小节）。
- **输出**：密钥长度（比特）、辅助数据大小、Gen/Rep 耗时。
- **验收**：d_H(w,w′) ≤ t 时 R′=R 恒成立；P 中不含 w 明文（可加互信息检查）。

### 1.4 生物DID生成与KGC-TEE私钥派生（对应方向1表述，须实现）
- **目的**：用户ID+生物密钥→去中心化生物DID；KGC 在可信执行环境（TEE）中基于生物DID 派生 SM9 私钥。
- **功能**：
  - DID 构造：`didsm9:<user_id>:<SM3 哈希>`（与专利主成果一致，哈希全部国密 SM3）；DID 文档含验证材料；注册登记表（ID_u ↔ DID ↔ key_hash）供 AS 绑定校验；冲突自动重试；
  - KGC-TEE 派生：私钥派生程序在 TEE 隔离区运行（无硬件 SGX 时用**独立进程模拟 TEE** + 主密钥不进日志），输出私钥与**派生审计日志**（时间、DID、操作者）。
- **验收**：DID 唯一且可解析；无 TEE 时模拟方案在论文中注明；审计日志可查询。

### 1.5 SM9 密码引擎
- **目的**：SM9 签名/验签（与可选的密钥协商）。
- **功能**：KGC 初始化、用户私钥派生（基于标识 ID）、Sign/Verify。
- **输出**：签名大小、签名/验签耗时（微秒/毫秒级）。
- **验收**：真 SM9 库优先（如 gmalg）；不可用时可用模拟实现但必须标注（论文会注明）。

### 1.6 安全模板与密钥撤销（定位：对比方向——专利主方案为非存储式，安全模板作路线对比）
- **目的**：模板可撤销、不可逆。
- **功能**：带密钥随机投影变换生成安全模板；支持版本号；密钥从模板经 KDF 派生。
- **验收**：更换投影密钥后旧模板失效（撤销实验可用）。

### 1.7 稳定比特"多数投票"数据来源（数据缺口修正）
- **现状**：LFW 每人平均仅 2.3 张照片，≥5 张的人数不足 500。
- **方案（双样本设计，已决策）**：取 ≥2 张照片的人 ≥300 人（库内约 1680 人满足）：A 图录入（+扰动副本 K 份投票模拟多采样）、B 图验证（真实跨条件样本+扰动）；异人随机配对 ≥5000 对测 FAR；KRR 分两档报告（KRR_真实=跨条件恢复率 / KRR_扰动=同源扰动恢复率）；先 30 人预试验定 RS 纠错能力基线。

### 1.8 Kerberos AS-REQ 重构
- **目的**：以 SM9 签名替代口令校验的初始认证。
- **功能**：AS（验签+时间戳+nonce 防重放）、TGS、Service、Client 四角色；消息 M = ID‖DID‖ts‖nonce；签发 TGT/ST；**票据载荷加密 SM4（全链路国密化，保留标准票据格式）**；时间戳窗口 30min（NTP）。
- **输出**：认证成功/失败、各阶段耗时、票据内容（结构化）。
- **验收**：篡改 M 或重放旧请求必须失败；时间窗口 Δ 可配置。

### 1.9 实验 A1：密钥可恢复性
- **输入**：LFW 双样本（≥300 人 × A/B 两张：A 录入+扰动投票，B 验证+扰动；异人配对 ≥5000 对；见 1.7）。
- **输出**：KRR（密钥恢复率）、FAR、FRR、ROC/AUC、EER；阈值扫描曲线（步长 0.01）。
- **数据文件**：`expA1_krr_threshold.csv`、`expA1_roc_curve.csv`、`expA1_genuine_impostor.csv`、`expA1_summary.csv`。
- **验收**：论文将引用 KRR/EER 数值，请保证数值与代码可复现（固定随机种子）。

### 1.10 实验 A2：噪声鲁棒性
- **输入**：对特征向量/比特串注入受控噪声（高斯扰动/比特翻转，强度梯度）。
- **输出**：密钥恢复成功率 vs 噪声强度曲线（同人配对）。
- **数据文件**：`expA2_noise_robustness.csv`。

### 1.11 实验 A3：端到端认证全流程
- **输入**：注册→认证完整链路（1.1–1.8 串联）。
- **输出**：各阶段时延明细、成功率、失败原因分类统计。
- **数据文件**：`expA3_e2e_results.csv`、`expA3_stage_latency.csv`。

### 1.12 实验 A4：性能对比
- **对比基线**：①标准口令 Kerberos（AES 套件）；②国密算法替换版 Kerberos（SM2/SM4 方案，见文献[21]）；③本文方案。
- **输出**：AS-REQ 全流程时延（本地域）、签名/验签时延、消息尺寸。
- **数据文件**：`expA4_performance.csv`、`expA4_message_sizes.csv`。

### 1.13 实验 A5：攻击用例（方案一）
| 用例 | 动作 | 预期 | 输出 |
|---|---|---|---|
| A5-1 重放 | 重放旧 AS-REQ（过期 ts/重复 nonce） | 拒绝 | 拦截率 |
| A5-2 伪造 | 篡改 M 后不重签名 | 验签失败 | 拦截率 |
| A5-3 冒用 | 他人 DID 绑定伪造 | 绑定校验失败 | 拦截率 |
| A5-4 泄露 | 辅助数据 P/模板泄露后的恢复尝试 | 无法恢复特征与密钥 | 攻击成功率（应≈0） |
| A5-5 暴力破解 | 连续错误认证尝试（阈值 3 次） | 熔断触发：is_blocked、删除会话/票据、强制重注册 | 熔断触发率、恢复流程正确性 |
- **数据文件**：`expA5_attack_results.csv`。

## 2. 方案二需求点（ST票据 + P2PVPN）

### 2.1 设备身份与 ST 票据
- **功能**：设备 DID 生成（基于设备唯一标识）；KDC 签发 ST 票据（字段：Realm、Principal=DID_dev、SName、NetPerm 组网权限{网段/带宽/时段}、Times、签名）；票据签名可验证、可撤销、到期自动失效。
- **输出**：票据结构（JSON/结构化）、签发/验证耗时。
- **验收**：伪造/篡改/过期票据必须验证失败。

### 2.2 SM9 授权委托（代理签名，可简化）
- **功能**：KDC 将授权验证能力委托给中继（代理签名密钥）；中继验证授权但不持有 KDC 主密钥。
- **验收**：中继无法伪造新授权（用测试证明）。

### 2.3 P2P 组网与中继三重验证
- **功能**：节点发现；入网提交（DID_dev + ST + 授权 + nonce + ts）；中继依次验证 ①授权有效性 ②ST 签名与时效 ③DID 一致性（挑战应答）；通过后分配虚拟地址。
- **输出**：准入结果、各验证阶段耗时。
- **验收**：合法节点通过，过期/冒用/伪造节点全部拒绝。

### 2.4 SM9 密钥协商与安全隧道
- **功能**：两节点以 DID 为公钥执行 SM9 密钥协商 → 会话密钥 → 加密封装（SM4）+ 完整性（SM3）。
- **输出**：握手轮次、握手耗时、隧道吞吐。
- **验收**：中继无法解密流量（可测试中继侧仅见密文）。

### 2.5 特征流量整形（可选项，建议实现）
- **功能**：隧道帧填充（消长度特征）+ 速率平滑（消突发性）。
- **输出**：整形前后包长分布、间隔分布、吞吐、带宽冗余率。
- **验收**：分布熵增加可量化、冗余率 ≤15%。

### 2.6 实验 B1：准入功能
- **输入**：三类节点（合法/过期票据/DID 冒用）。
- **输出**：准入正确率（应为 100% 分类正确）、验证时延构成。
- **数据文件**：`expB1_access_results.csv`。

### 2.7 实验 B2：扩展性梯度
- **输入**：节点规模 N = 10/50/100/200（真实进程或 NS-3 仿真）。
- **输出**：准入时延中位数、聚合吞吐、端到端时延、丢包率、中继 CPU/内存。
- **数据文件**：`expB2_scalability.csv`。

### 2.8 实验 B3：隧道与整形
- **输入**：三型业务流（周期型/突发型/交互型）。
- **输出**：吞吐、时延抖动、整形前后分布对比。
- **数据文件**：`expB3_tunnel_shaping.csv`。

### 2.9 实验 B4：攻击用例（方案二）
| 用例 | 动作 | 预期 |
|---|---|---|
| B4-1 重放 ST | 重放已用/过期票据 | 拒绝 |
| B4-2 伪造授权 | 无 KDC 密钥构造授权 | 验签失败 |
| B4-3 DID 冒用 | 合法票据+错误私钥 | 挑战应答失败 |
| B4-4 恶意中继 | 中继侧观察隧道 | 仅密文 |
- **数据文件**：`expB4_attack_results.csv`。

## 3. 方案三需求点（MCP 双DID + 签名链）

### 3.1 双 DID 模型与分级授权
- **功能**：用户生物 DID（责任主体）+ Agent 设备 DID（执行主体）；KDC 分别签发 ST_net（组网权限，中继验证）与 ST_data（数据/协同权限，MCP 服务端验证）。
- **输出**：两类票据、签发耗时。

### 3.2 双签名链构造
- **功能**：指令 Cmd → σ_agent = Sign(设备私钥, H(Cmd‖ts‖req_id)) → σ_user = Sign(生物私钥, H(Cmd‖σ_agent‖ctx))；请求携带双票据。
- **输出**：签名链大小、构造耗时。

### 3.3 MCP 服务端四步验证
- **功能**：①票据校验（双票据签名+时效+权限）②签名链校验 ③DID 一致性 ④权限匹配（Cmd 动作 vs ST_data 权限集合）；通过后转发+审计。
- **输出**：验证耗时、各步耗时、拒绝原因。
- **验收**：篡改/越权/重放指令必须拒绝；正常指令 100% 通过。

### 3.4 实验 C1：分级授权功能
- **场景**：A 数据查询（用户授权 Agent 查库）、B 协同任务（多 Agent 链式）、C 跨域转发（经 P2PVPN 中继访问异网 MCP）。
- **输出**：三场景跑通记录、授权-拒绝日志。
- **数据文件**：`expC1_scenarios.csv`。

### 3.5 实验 C2：签名链性能
- **输入**：并发 100/500/1000 req/s。
- **输出**：单请求验证时延（p50/p90/p99）、QPS 上限。
- **数据文件**：`expC2_performance.csv`。

### 3.6 实验 C3：指令攻击与正确性
- **输入**：≥500 条指令（正常 60% / 篡改 16% / 越权 16% / 重放 8%，比例可调）。
- **输出**：正常通过率、篡改检出率、越权拒绝率、重放拒绝率。
- **数据文件**：`expC3_instruction_results.csv`。

### 3.7 实验 C4：安全属性对比
- **对比**：标准 Kerberos / 国密 Kerberos / OAuth 2.1 直连 MCP / 本文方案。
- **维度**：抗重放、抗伪造、权限粒度、身份-权限绑定、隐私保护、国产合规、单点故障。
- **输出**：定性+半定量矩阵表（每格给出依据，能实测的给数值）。
- **数据文件**：`expC4_security_matrix.csv`。

## 5. 输出数据规约（论文取用格式）

1. **CSV 规约**：每实验一个 CSV；首行列名为英文字段；同一实验的统计量与明细分开存；数值保留 ≥4 位有效数字。
2. **确定性**：所有随机过程固定 seed（在元数据行注明 seed 值），保证复跑结果一致。
3. **元数据**：每个输出目录放 `README.md`，记录：实验名、代码入口、环境（Python 版本、依赖）、数据规模、seed、运行耗时。
4. **图表**：自动绘图输出 PNG（≥300dpi）+ 源数据 CSV；图名与论文图号对应（如 `fig_A1_krr_threshold.png`）。
5. **命名**：统一 `expA1_xxx.csv` 前缀规则（A/B/C 对应三方案），论文将按此索引。
