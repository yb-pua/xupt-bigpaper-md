### 2.3 CSV 全局规约

1. **命名**：前缀统一 `expA1_-expA5_`（方向一）、`expB0_/expB1_-expB4_`（方向二）、`expC0_/expC1_-expC4_`（方向三）。文件名一律见 §3/§4/§5 与 §6 索引。
2. **列**：CSV 首行列名为英文字段（§6 索引为准）；同一实验统计量与明细分开存文件。
3. **精度**：数值保留 ≥4 位有效数字。
4. **确定性**：全链路固定 seed（README 记录 seed 值），复跑结果一致。
5. **元数据**：每个 results 子目录附 `README.md`：实验名、代码入口、环境（Python 版本/依赖）、数据规模、seed、运行耗时、模拟标注。
6. **图表**：自动绘图输出 PNG（≥300dpi）+ 源数据 CSV，图名对应论文图号（如 `fig_C2_latency.png`）。

### 2.4 跨方向数据契约

- **ticket_id 审计链**：KDC 签发→（方向二）中继验证日志→（方向三）MCP 调用→审计记录，全链以 ticket_id 关联可回溯。`audit_logger.log(ts, ticket_id, action, result, principal)`。
- **verify_ticket(ticket, service, claims_checker=None)**：方向一实现；方向二传 NetPerm 校验、方向三传权限集合；单测须注入假 claims 证明被调用。
- **sm9 预留接口**：`verify_chain(sigs, docs, dids)`（方向三签名链）、`key_exchange_initiator/responder`（方向二/三密钥协商）、`proxy_sign/proxy_verify`（方向二授权委托）。方向一若未实现，由使用方向补齐实现，不得影响方向一实验。
- **make_device_did(device_id, owner_user_id)**：方向二/三设备 DID 统一走方向一 did.py。
- **绑定表**：user_bio_did ↔ device_did（方向二 B1 联动校验；方向三 Agent=owner 设备）。
- **票据单次使用**：ST 提交缓存（重放第二次拒绝）——方向二/三共用。

### 3.3 核心库接口与验收（core/，11 模块）

| 模块 | 接口 | 验收 |
|---|---|---|

| mcp_protocol.py | `build_tools_call(req_id, tool, args)`；`inject_tickets(msg, st_data, st_net)`；`parse_request(msg, headers)` | 报文符合 MCP `tools/call` JSON-RPC 结构；X-ST-Ticket 双头部可解析 |
| mcp_agent.py | `init(env_id, owner_user_id, sm9, kdc)`；`sign_chain(cmd, ts, req_id, ctx)`；`build_request(cmd, st_net, st_data)` | 双签名链序正确（σ_agent 先、σ_user 后）；请求可被服务端四步验证通过 |
| claims_checker.py | `match(action, tool, claims)` → allow/deny | tool+action 级权限匹配正确；tool 不在 claims 拒绝 |
| mcp_server.py | `handle_call(request)`：四步验证→权限匹配→转发→审计；`verify_four_steps(...)` 单步可测 | 篡改/越权/重放/DID 冒用 100% 拒绝；正常 100% 通过；每步耗时可测 |
| mcp_gateway.py | `admit(req)`（验证 ST_net+SM9 授权+DID 一致性）；`forward(msg)` | 跨域转发链路可行；载荷不解密；ST_net 失效拒绝 |
| oauth_baseline.py | `OAuthBaseline`：授权码+PKCE 换 token；`call_tool(token, cmd)`；`cache_auth_state=True` 复刻授权态缓存复用 | 与本文同环境可对比；调用者混淆缺陷可复现（C3-6 打穿） |
| noauth_baseline.py | `NoAuthBaseline.call_tool(cmd)` | 无认证直连工具，安全功能=0 |

> 方向一预留接口 `verify_chain`（签名链）/`proxy_*`/`key_exchange_*` 若 core 未实现，方向三补齐实现，不得影响方向一实验。

### 5.4 实验（C0-C4）

#### C0 Agent 身份锚点可行性（输出 1 CSV）
- 流程：生成 4 类环境唯一标识 → `make_device_did` 派生 Agent 设备 DID → 唯一性/冲突重试；环境重建→新标识→重注册走登记表；克隆→相同标识→注册去重。
- 输出：`expC0_agent_id.csv`（env_type, env_id, device_did, collision, re_register, ok）。

#### C1 分级授权功能（输出 2 CSV）
- 场景 A 数据查询（ST_data 四步验证）；场景 B 协同任务（多 Agent 链式，每级双签名链+双 ST）；场景 C 跨域转发（经 mcp_gateway 验证 ST_net）；审计 ticket_id 关联链。
- 输出：`expC1_scenarios.csv`（scenario, steps, passed, reject_reason, latency_ms）；`expC1_audit.csv`（calls, chain_complete_rate, audit_missing_rate）。

#### C2 签名链性能（输出 1 CSV）
- 并发 100/500/1000 req/s；单请求验证时延 p50/p90/p99、QPS、消息尺寸开销（本文 vs OAuth 基线）。
- 输出：`expC2_performance.csv`（scheme, concurrency, p50_ms, p90_ms, p99_ms, qps, msg_bytes）。

#### C3 指令攻击与正确性（输出 3 CSV）
- ≥500 条指令（正常 60%/篡改 16%/越权 16%/重放 8%），三方案（无管控/OAuth/本文）各跑一遍。

| 编号 | 用例 | 动作 | 预期 |
|---|---|---|---|
| C3-1 | 篡改指令 | 改动作/参数不重签 | 本文拦截；OAuth/无管控放行 |
| C3-2 | 越权调用 | tool 不在 ST claims | 本文拦截（tool 级）；OAuth server 级粒度放行 |
| C3-3 | 重放 | 旧指令/旧 ST 重发 | 本文拦截；其余放行 |
| C3-4 | 伪造票据 | 无 KDC 密钥构造 ST | 本文验签失败 |
| C3-5 | DID 冒用 | 合法票据+错误私钥 | 本文链式验签/一致性失败 |
| C3-6 | 调用者混淆 | OAuth token 复用于另一调用者 | OAuth 被打穿（授权态缓存复用）；本文每请求带认证器拦截 |

- 消融（同批指令，本文配置三档）：全量 / 去用户签名层 / 去 ST_data。
- 输出：`expC3_instruction_results.csv`（case_type, scheme, total, passed, blocked, block_rate）；`expC3_attack_matrix.csv`（attack_type, scheme, attempts, blocked, block_rate）；`expC3_ablation.csv`（config, case_type, block_rate, note）。

#### C4 安全属性对比矩阵（输出 1 CSV）
- 7 维：抗重放、抗伪造、权限粒度（tool 级）、调用级绑定（防调用者混淆）、审计归因、撤销/生命周期、国产合规；方案：标准 Kerberos / 国密 Kerberos / OAuth 2.1 直连 / 本文。
- 输出：`expC4_security_matrix.csv`（dimension, scheme, value, basis）。
