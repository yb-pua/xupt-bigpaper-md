# 方向二（P2PVPN）实验设计详解

> 配套：`实验需求点清单.md` 第 2 节（B1-B4 骨架）。本文档细化方向二实验的构造方法、测量方法、对比试验设计与公平性条件，代码侧可直接照此实现。
> 方向二不依赖生物数据（设备身份为主），实验为"网络+密码"两类：协议正确性（准入/攻击）与网络性能（扩展性/隧道/整形）。

---

## 1. 实验目标：要回答的 4 个问题

| 问题 | 对应实验 | 证明方式 |
|---|---|---|
| Q1 票据化准入是否有效拦截非法节点？ | B1 + B4 | 6 类非法节点全部拒绝，合法节点 100% 通过 |
| Q2 引入票据/SM9 的开销是否可接受？ | B1（时延构成）+ B2 | 与"无票据 P2PVPN"基线对比，准入时延增量量化 |
| Q3 P2P 去中心化相比中心化 VPN 的扩展性/可用性优势？ | B2 | 与 OpenVPN 网关对比吞吐/时延/故障影响 |
| Q4 特征流量整形是否隐藏流量特征、代价多大？ | B3 | 分布熵/KL 散度提升 + 带宽冗余率量化 |

## 2. 实验环境与部署方式（关键决策）

**推荐：真实进程部署（Docker/容器）为主，NS-3 仿真为可选扩展。**

理由：
- 实验室 KVM/容器平台可直接起真实 Python 节点，攻击注入、抓包、时延测量都比仿真真实；
- 200 节点梯度在服务器上可行（单节点进程 <50MB 内存，1 中继 + 199 设备）；
- NS-3 学习成本高且与论文代码脱节，仅在需要 1000+ 节点或真实网络拓扑时才用。

部署形态：
```
Docker Compose 编排：
  kdc          # KDC：ST 票据签发 + SM9 授权（1 个）
  relay-1      # P2P 中继：三重验证 + 转发（1~2 个）
  device-1..N  # 设备节点：DID + SM9 私钥 + 业务流生成器（N 个）
  controller   # 测试控制台：发起并发入网、注入攻击、采集指标
```
网络：单机桥接网络（同网段，忽略 NAT 穿越——NAT 穿越列为真实部署扩展项，论文中说明）。

## 3. 代码侧组件清单（方向二）

| 模块 | 功能 | 验收点 |
|---|---|---|
| `st_ticket.py` | ST 票据结构（Realm/Principal=DID_dev/SName/NetPerm/Times/Sig），签发与验证 | 篡改/过期/伪造票据验证失败 |
| `sm9_engine.py` | KGC 初始化、设备私钥派生、签名/验签、密钥协商 | 可复用方案一 SM9 引擎 |
| `kdc.py` | 设备注册、授权签发（DID+policy）、ST 签发、委托密钥生成 | 授权可验证、中继无主密钥 |
| `relay.py` | 三重验证（授权/票据/DID 挑战应答）、转发、票据单次使用缓存 | 三类节点分类正确 |
| `device.py` | 设备 DID 管理、入网流程、密钥协商、隧道收发、业务流生成 | 入网-通信全链路 |
| `shaping.py` | 隧道帧填充 + 速率平滑（可选） | 冗余率 ≤15% |
| `test_controller.py` | 实验编排：并发入网、攻击注入、指标采集、CSV 输出 | 输出符合规约 |

## 4. 实验 B1：组网准入功能与验证时延

### 4.1 节点类别构造方法（代码要能生成这 6 类）

| 类别 | 构造方法 | 预期结果 |
|---|---|---|
| 合法节点 | KDC 正常签发 ST + 设备持有对应私钥 | 准入通过 |
| 过期票据 | ST 的 Times 已过期（签发后等待或时钟后拨） | 拒绝（时效） |
| 重放票据 | 同一 ST 提交两次 | 第二次拒绝（单次使用缓存） |
| 伪造票据 | 无 KDC 私钥，随机密钥签 ST | 拒绝（验签失败） |
| 篡改票据 | 合法 ST 修改 NetPerm 字段 | 拒绝（验签失败） |
| DID 冒用 | 合法 ST + 另一设备的私钥应答挑战 | 拒绝（挑战应答失败） |

### 4.2 测量
- 每类节点重复 ≥100 次，统计分类正确率（应为 100%）；
- 合法节点记录验证时延构成：授权验签 / ST 校验 / 挑战应答 三段耗时（p50/p90）；
- 数据文件：`expB1_access_results.csv`（列：case_type, result, verify_authorize_ms, verify_st_ms, challenge_ms, total_ms）。

### 4.3 对比（Q2 数据来源）
同环境跑"无票据 P2PVPN"（静态预共享密钥验证）的入网时延，得**票据化开销增量** = 本文准入时延 − 基线准入时延。

## 5. 实验 B2：扩展性梯度（核心对比试验）

### 5.1 规模与拓扑
- N = 10 / 50 / 100 / 200，拓扑：单中继星型（主）+ 双中继（容错场景）
- 负载模型：每设备恒定背景流 1 Mbps（UDP 定长包）+ 测试流测量

### 5.2 测量指标
| 指标 | 测量方法 |
|---|---|
| 准入时延（并发入网） | controller 同时触发 N 节点入网，记录完成时间 p50/p90 |
| 聚合吞吐 | 全网有效业务字节/秒（中继转发口径） |
| 端到端时延 | 测试流往返时延 p50/p90 |
| 丢包率 | 测试流丢包比例 |
| 中继 CPU/内存 | 采样记录 |

### 5.3 对比基线（Q2+Q3 数据来源）
| 基线 | 实现方式 | 对比目的 |
|---|---|---|
| 无票据 P2PVPN | 静态预共享密钥准入 + 相同隧道（复用本文隧道代码，仅替换准入） | 量化票据化开销 |
| 中心化 VPN | OpenVPN（证书认证）单网关 + 同规模客户端 | 量化 P2P 去中心化增益 |
| （可选）WireGuard | wg 静态密钥 + 中心协调 | 与主流方案对照 |

### 5.4 公平对比条件（必须声明并遵守）
1. **同硬件同网络**：全部基线跑在同一服务器/桥接网络；
2. **同负载模型**：背景流、测试流、节点数完全一致；
3. **功能等价声明**：各基线实现的"准入控制"等级不同（静态密钥 = 持有性验证；证书 = 身份绑定验证；本文 = 身份+策略+时效），对比表注明，不做不公平的"功能碾压"；
4. **同指标口径**：吞吐/时延口径统一（中继或网关口径）。
5. **故障注入对比（Q3）**：分别 kill 中继（本文）与网关（OpenVPN），测量会话中断范围与恢复时间——展示去中心化容错优势。

### 5.5 输出
- `expB2_scalability.csv`（列：N, scheme, admit_p50, admit_p90, throughput_mbps, e2e_latency_ms, loss_rate, relay_cpu_pct, relay_mem_mb）
- 扩展性曲线图 2 张：①准入时延 vs N（三基线叠加）②聚合吞吐 vs N。

## 6. 实验 B3：隧道与特征流量整形

### 6.1 业务流模型（三型）
| 类型 | 生成方式 | 特征 |
|---|---|---|
| 周期型 | 固定 1 包/秒 × 定长 | 强周期性（心跳/遥测） |
| 突发型 | 泊松过程成突发 | 高突发性（文件同步） |
| 交互型 | 请求-应答模式 | 双向交替（查询） |

### 6.2 测量
- 整形前/后各抓包 ≥10 min：包长分布、包间隔分布；
- **隐藏效果量化**：分布熵 H、与参考分布的 KL 散度（整形后应接近均匀/目标分布）；
- **代价量化**：带宽冗余率 = (整形后流量 − 原始流量)/原始流量；时延增量。

### 6.3 对比
- 同流量模型下：未整形隧道 vs 整形隧道；
- 输出 `expB3_tunnel_shaping.csv` + 分布对比图（包长直方图、间隔分布、熵增益表）。

## 7. 实验 B4：攻击用例（Q1 深化）

| 用例 | 注入方法 | 预期 | 量化 |
|---|---|---|---|
| 重放 ST | 合法 ST 二次提交 | 拒绝 | 拦截率 |
| 伪造授权 | 无主密钥构造 SM9 授权 | 验签失败 | 拦截率 |
| 伪造 ST | 随机密钥签 ST | 验签失败 | 拦截率 |
| 篡改 ST | 改 NetPerm/Principal 后重签（无密钥） | 验签失败 | 拦截率 |
| DID 冒用 | 合法票据+错误设备私钥 | 挑战应答失败 | 拦截率 |
| 恶意中继窃听 | 中继侧 dump 隧道流量 | 仅密文 | 明文泄露率=0 |
| 过期续访 | 持续验证周期复核 | 断链/拒绝 | 拦截率 |

- 输出：`expB4_attack_results.csv`（列：attack_type, attempts, blocked, block_rate, note）。
- 附加：与基线对比表（无票据 P2PVPN 对同用例的拦截情况——可预期静态密钥方案在伪造/冒用上防护弱，形成安全差距证据）。

## 8. 对比试验总体呈现（论文第6章用）

1. **安全-性能二维权衡图**：横轴=准入时延开销，纵轴=攻击拦截率（7 用例均值），散点=本文/无票据P2PVPN/OpenVPN/（可选）WireGuard——一图说明"安全增益 vs 开销"；
2. **扩展性曲线图**：准入时延、吞吐 vs N；
3. **故障注入表**：中继/网关故障后的中断范围、恢复时间；
4. **安全属性矩阵**（定性+实测）：抗重放、抗伪造、权限粒度、动态撤销、端到端保密、单点故障、国产合规 7 维 × 4 方案。

- CSV 命名 `expB1/B2/B3/B4_*.csv`；固定 seed；输出目录附 README（环境、规模、seed、耗时）；
- 图表 PNG ≥300dpi + 源数据；

## 10. 一个提醒（避免踩坑）

- 对比试验最容易翻车的点是"基线没实现同等功能就比性能"——务必在论文与代码注释中写清各基线实现的安全功能等级；
- 200 节点同时入网时 KDC 单点签发会成为瓶颈，正好作为"KDC 离线不阻断既有会话"的容错场景，而非缺陷——实验设计上主动制造该场景并测量恢复。
