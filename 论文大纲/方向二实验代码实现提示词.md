## 2. 技术约束（不可偏离）

| 项 | 实现 |
|---|---|
| SM9 | **gmalg 单库**（SM9/SM3/SM4 全用）；某接口不可用→模拟实现并标注"SM9 模拟" |
| 设备 DID | 复用方向一 `did.py` 风格：`make_device_did(device_id)` → `didsm9:<device_id>:<SM3 哈希>`，冲突重试 |
| 授权 | 授权 A = {DID_dev, policy=NetPerm, exp, Sig_KDC}；NetPerm = {服务集合, 带宽上限, 时段} |
| 代理签名 | KDC 生成代理签名密钥 + **warrant（授权书）**：仅可签发"已通过三重验证设备的会话准入凭证"（绑定 DID+NetPerm+有效期），不能签发新授权/新票据 |
| 会话准入凭证 | 中继签发，数据面凭此快速放行；验证方先验 warrant 再验签名 |
| ST 票据 | 字段 {Realm, Principal=DID_dev, SName, NetPerm, Times={Start,End}, CAddr, Sig}；**时间戳窗口 30min**；含 **ticket_id**；载荷格式 JSON |
| 三重验证 | ①授权验签（KDC 公钥/代理验证）②ST 校验（签名+时效+单次使用缓存）③DID 一致性（挑战应答：设备用 SM9 私钥签 nonce，中继用 DID 验） |
| 绑定校验（联动） | 设备入网须关联已认证用户（绑定表 user_bio_did↔device_did，模拟生物DID 即可）；无绑定/绑定未认证 → 拒绝 |
| 隧道 | SM9 密钥协商（两端以对方 DID 为公钥）→ 会话密钥一致；**SM4 加密载荷 + 明文虚拟地址头**（中继按地址头路由、不解密载荷） |
| 整形 | 帧填充（固定档/随机填充）+ 速率平滑（令牌桶）；目标分布=均匀；**冗余率 ≤15%** |
| NAT | 虚拟 NAT 层类型可配：全锥/受限锥/端口受限/对称；打洞判定逻辑与 RFC 4787/5389/5766 理论矩阵一致（写死判定表） |
| 部署 | **本机多进程**（不封装 Docker）：coordinator 用 `subprocess` 拉起 kdc/relay/device，localhost 不同端口 |
| 哈希 | 全链路 **SM3**，禁止 SHA-256/BLAKE2b |
| 随机 | 全局固定 SEED（README 记录） |
| 匿名 | 代码/注释/README 不得出现作者/学校等身份信息 |
| 审计 | 统一 `audit_logger`（ts, ticket_id, action, result, principal）——方向一若未提供则方向二实现 |

## 3. 数据（程序生成，无生物数据）

- 设备标识：程序生成 N 台（10/50/100/200 梯度用）；设备 DID 由 make_device_did 派生
- 绑定表：程序生成 N_user×M_device（含绑定/未绑定两类，模拟生物DID）
- 业务流：三型（周期型 1 包/s 定长 / 突发型泊松突发 / 交互型请求-应答）各 ≥10min
- NAT 类型分布：程序假设（如均匀/偏对称），兜底率按其推导

## 4. 核心库（core/，接口+验收）

| 模块 | 接口 | 验收 |
|---|---|---|
| st_ticket.py | `issue_ticket(principal, service, netperm, times)`；`verify_ticket(ticket, service, claims_checker=None)` | 篡改/过期/伪造/重放全部失败；claims_checker 被调用；ticket_id 生成 |
| authorization.py | `issue_auth(did_dev, policy, exp)`；`proxy_delegate(warrant)`；`proxy_verify(auth, warrant)`；`issue_session_credential(did, netperm, exp)` | 授权书外签发凭证验证失败 |
| discovery.py | `register_device(did, addr)`；`find_node(did)`；`build_topology(relays)` | 发现→入网→通信全链路可行 |
| kdc.py | `register_device()`；`issue_auth()`；`issue_ticket()`；`delegate_proxy()` | 授权/票据可验证；代理密钥分发不泄漏 KDC 主密钥 |
| relay.py | `admit(device_req)`（三重验证+绑定校验）；`issue_session_credential()`；`forward(pkt)`（按虚拟地址头路由） | 6 类节点分类正确；转发不解密载荷 |
| device.py | `enroll()`；`admission()`；`negotiate_tunnel()`；`flow_gen(type, rate)` | 入网-通信全链路 |
| tunnel.py | 复用 SM9 `key_exchange_initiator/responder`（方向一若未实现则方向二补齐）；`frame_encrypt/decrypt`（SM4）+ SM3 完整性 | 两端会话密钥相等；中继 dump 仅见密文 |
| shaping.py | `shape(pkt, target_len, rate)` | 冗余率 ≤15%；熵提升可量化 |
| nat_layer.py | `nat_type`（可配 4 类）；`try_punch(src_type, dst_type)` | 判定结果与理论矩阵一致 |
| audit_logger.py | `log(ts, ticket_id, action, result, principal)` | 全链路以 ticket_id 关联可回溯 |

> 方向一预留接口 `key_exchange_*` / `proxy_sign` / `proxy_verify` / `verify_ticket(claims_checker)` 若方向一 core 未实现，方向二补齐实现，不得影响方向一实验。

## 5. 实验（experiments/，独立可跑 + run_all 汇总）

### B0 组网基础设施（D0：节点发现+拓扑+NAT 条件）
- 流程：协调服务注册/公告 + find_node（DHT 简化）→ 中继邻居表星型拓扑 → 新设备"发现→入网→与已准入设备通信"；虚拟 NAT 层测代表性类型对直连成功率 + 兜底率推导
- 输出：`expB1_discovery.csv`（discover_ms, topology_entries, connect_ok）、`expB1_nat.csv`（nat_type_pair, direct_ok, relay_needed, latency_direct_ms, latency_relay_ms）

### B1 准入功能（D1/D2/D3）
- 流程：6 类节点各 ≥100 次（合法/过期/重放/伪造/篡改/DID 冒用）+ 无绑定节点；准入时延三段分解（授权验签/ST 校验/挑战应答 p50/p90）；会话准入凭证签发后数据面放行
- 基线（同环境）：无票据 P2PVPN（静态预共享密钥准入 + 复用本文隧道，仅替换准入）→ 票据化开销增量
- 输出：`expB1_access_results.csv`（case_type, result, verify_authorize_ms, verify_st_ms, challenge_ms, total_ms）

### B2 扩展性（D3/D4）
- 流程：N=10/50/100/200（本机多进程），每设备恒定背景流 1Mbps UDP + 测试流；vs OpenVPN（证书认证）同环境同负载；故障注入 kill 中继 vs kill 网关 → 中断范围/恢复时间
- 指标：准入时延 p50/p90、聚合吞吐、e2e 时延、丢包率、中继 CPU/内存
- 输出：`expB2_scalability.csv`（N, scheme, admit_p50, admit_p90, throughput_mbps, e2e_latency_ms, loss_rate, relay_cpu_pct, relay_mem_mb）、`expB2_failover.csv`（scheme, failure_point, session_break_range, recovery_time）

### B3 隧道与整形（D5/D6）
- 流程：三型业务流整形前后各抓包 ≥10min；包长/间隔分布、分布熵 H、与均匀参考分布 KL 散度、带宽冗余率、时延增量；SM9 密钥协商握手轮次/时延、隧道吞吐 vs **TLS 隧道基线（python ssl 自实现，同环境）**
- 输出：`expB3_tunnel_shaping.csv`（flow_type, metric, pre, post, entropy, kl_div, redundancy_rate, latency_delta）

### B4 攻击（D1/D2/D5）
| 用例 | 动作 | 预期 |
|---|---|---|
| 重放 ST | 合法 ST 二次提交 | 拒绝 |
| 伪造授权 | 无 KDC 主密钥构造授权 | 验签失败 |
| 伪造 ST | 随机密钥签 ST | 验签失败 |
| 篡改 ST | 改 NetPerm/Principal 后重签（无密钥） | 验签失败 |
| DID 冒用 | 合法票据+错误设备私钥 | 挑战应答失败 |
| 恶意中继窃听 | 中继侧 dump 隧道载荷 | 仅密文（明文泄露率=0） |
| 过期续访 | 持续验证周期复核 | 断链/拒绝 |
| 代理伪造（warrant 越界） | 中继用代理密钥签授权书外凭证（新授权/新票据） | 验证失败 |
- 输出：`expB4_attack_results.csv`（attack_type, attempts, blocked, block_rate, note）、`expB4_proxy_forge.csv`（test, forge_ok, note）

## 7. 验收（全过才算完成）

1. `run_all.py` 从空 results 一键复现全部 CSV；
2. 抽查 3 组 CSV 数值与代码逻辑一致；
3. B1 自测：6 类节点分类正确率 100%（合法通过、其余拒绝）；无绑定节点拒绝；
4. 代理伪造自测：授权书范围外签发凭证 100% 无效；
5. 隧道自测：两端协商密钥相等；中继 dump 隧道载荷仅见密文（明文泄露率=0）；
6. 整形自测：冗余率 ≤15%；整形后包长/间隔熵提升、KL 散度下降；
7. NAT 自测：类型对直连判定与理论矩阵一致；兜底率按分布推导可复算；
8. 超 30min ST 100% 拒绝；重放 ST 第二次拒绝（单次缓存）；
9. 匿名检查：`grep -rn "姓名\|学校\|学院" core/ experiments/ README.md` 零命中；
10. 常量可查：30min / ≤15% / ticket_id / didsm9 / NetPerm / 授权书(warrant)。
