## 3. 方向一设计（C1-C6）

### 开题主张（方向一）

① 模糊提取生成稳定生物密钥（多数投票+码辅助数据，含噪可靠恢复）；② 用户ID+生物密钥→生物DID，KGC-TEE 派生 SM9 私钥；③ 重构 AS-REQ（"ID+DID+时间戳"SM9 签名替代口令），阻断票据伪造与重放。

### C1 生物密钥可恢复（实验 A1）

- **实验**：LFW 自有数据算成功率。主指标 KRR/FAR_key/FRR_key + Hamming 距离接受阈值 θ 扫描出 AUC/EER；投票增益消融（单张基线 vs 5 张，423 人档）支撑"多数投票"机制。数据口径见《代码汇总版》§3.1。
- **对比向**：无文献数值对比（Kuznetsov 2023 / Yirga 2025 / CCS2025 / Sulavko 2025 仅引言引用）。
- **论文位置**：3.3（方案）+ 3.7（实验）。

### C2 噪声鲁棒（实验 A2）

- **实验**：图片级加噪→重新恢复（用户口径）：cv2 五类扰动（高斯/亮度/旋转/模糊/遮挡）×强度梯度×KRR；注册侧加噪生成、认证侧加噪恢复；LFW 跨条件（A/B 图）等效噪声锚点标注在曲线，论证 RS(255,191,t=32) 容限覆盖真实噪声。
- **对比向**：无数值对比（Becker 2013 仅理论引用）。
- **论文位置**：3.3（方案）+ 3.7（实验）。

### C3 认证基线对比（实验 A4）

- **实验**：同环境自实现三基线——Password-Kerberos（RFC 4120）/ SM2-PKINIT（国密）/ 本文 SM9；**RSA-PKINIT 数据驱动待定**（数据差距过大则删）。
- **指标**：AS-REQ 全流程时延（p50/p90）、阶段分解（签名/验签/票据签发）、消息尺寸、成功率。
- **叙事**：安全价值在前（C4 拦截率）→ 代价在后（"增加多少代价换什么安全属性"）。
- **论文位置**：3.7（实验）。

### C4 攻击面（实验 A5）

| 攻击手段 | 攻击原理 | 本文防御机制 | 验证 |
|---|---|---|---|
| 黄金票据（Golden Ticket） | 窃取 KDC 主密钥→Mimikatz 伪造任意 TGT | KDC 主密钥 TEE 中生成/使用、不出 TEE | A3 审计 |
| 白银票据（Silver Ticket） | 窃取服务密钥→伪造任意 ST | 服务密钥 KDC-TEE 派生；服务访问前置 SM9 验签 | A5-2 |
| 重放 | 捕获请求/票据重放 | 时间戳 30min + nonce | A5-1 |
| 离线破解/Kerberoasting | 离线爆破服务账户口令 | 无口令；票据 SM4+密钥 TEE 管理 | A5-5 |
| 口令喷射 | 批量弱口令尝试 | 无口令+熔断（3 次锁定） | A5-5 |
| 票据传递（Pass-the-Ticket） | 窃取内存票据异地使用 | 票据绑定 DID+SM9 签名身份 | A5-3 |
| AS-REP Roasting | 未预认证账户离线破解 | 全部账户强制预认证 | A5-2 |
| 委派滥用 | 委派配置错误提权 | 不引入委派；代理签名受 NetPerm 限定 | B 系列 |
| 时间同步放宽 | 窗口过宽放大重放窗口 | 30min+nonce 双保险 | A5-1 |

- **对比向**：同用例集自实现拦截率（本文 vs 口令版）；Qatinah 2024 攻击面覆盖度声明。
- **论文位置**：3.6（安全分析）+ 3.7（实验）。

### C5 隐私论证（传统人脸认证 vs 本文）

4 步论证链（佐证文献）：
1. **传统存模板、模板可逆向重建**：Mai TPAMI 2019（41(5):1188-1202）；Shahreza ICCV 2023（3D 重建）；Gomez-Barrero & Galbally, Comput. Secur. 90, 2020（逆向综述）；**TIFS 2021**（攻击二值化+模糊承诺人脸系统，>83% 解锁 @FMR 0.1%——与本文链路同构，必引）；
2. **本文不存模板（σ+key_hash）**：ISO/IEC 24745:2022；Dodis 2004；
3. **生物特征不可撤销，本文可重注册**：ISO 24745 Renewability；Rathgeb & Uhl 2011；Nandakumar & Jain SPM 2015；
4. **存储变换模板也不安全**：Lacharme SECRYPT 2013（BioHashing 预映像攻击）；Shahreza FG 2024（Breaking Template Protection）。

对比表（论文 3.1 结尾）：存储内容（模板 vs σ+key_hash）/ 特征是否出本地 / 泄露后果（身份冒用 vs 无法恢复，A5-4 实测≈0）/ 可撤销性 / 认证凭据（静态模板 vs 动态密钥）。

- **论文位置**：**3.1 威胁模型与设计目标（动机：传统隐私缺陷→设计目标）+ 3.6（ISO 24745 对照+A5-4 验证）**——不放最后。
- 总结句："传统服务以'存储模板'换认证，泄露即身份终结；本方案'不存模板+特征不出本地+辅助数据不可逆'，泄露不致命、可重注册。"

### C6 认证判定链与熔断恢复

- **判定链**："认证判定 = Rep 恢复 bio_key' ∧ SM3(bio_key') == 登记 key_hash；RS 超纠错可能误纠错到错误码字，哈希校验兜底；σ 篡改仅致拒绝服务而非伪造通过。"
- **熔断分层恢复**：L1 会话重建（熔断 3 次→删会话/票据→Rep 恢复→重认证，bio_key/DID/授权不变）；L2 身份重置（Rep 连续失败→重新 Gen→显式更新 key_hash/DID/私钥→重新授权，低频事件）。
- **实验**：A3 异常路径（熔断→L1→断言 bio_key/DID/票据链不变）；A5-5（熔断触发率、L1 成功率、L2 兜底率——L2 应极低，与 A2 KRR 交叉印证）。
- **论文位置**：3.6（安全分析）。

## 4. 方向二设计（D0-D6）

### 开题主张（方向二）

设备 DID 关联 SM9 私钥 → KDC 对"设备DID+访问策略"生成 SM9 授权并委托 P2P 中继节点为代理签名者 → P2P 网络分布式组网实现节点发现与拓扑构建 → 代理签名者验证"SM9授权有效性+ST票据合法性+设备DID一致性"，为合法客户端提供通信中继 → SM9 密钥协商生成会话密钥+带特征流量整形安全隧道 → 实现组网准入控制与端到端通信安全结合。

### 关键决策（2026-08-17 拍板）

1. **中继=验证型网关**：中继验证 ST/授权/签名链后按 NetPerm 路由转发，**不碰明文**——保留"中继不可解密"主张（不推翻 D5），与方向三 MCP 兼容方案 B+C 复用。
2. **节点发现/拓扑构建=简化方案**：协调服务（controller 兼任）做设备注册/发现（DHT 简化替代）+ 中继邻居表构建星型拓扑；**仅证明可行**，不追求完整 DHT/NAT 穿越。
3. **特征流量整形必做**（开题承诺"带特征流量整形构建安全隧道"），B3 不降级。
4. **指标分层**：连通率/丢包率等为**性能面**参数（功能正确性+代价），与**安全面**参数（拦截率/不可解密/授权粒度）分开呈现。
5. **部署分两阶段**：阶段一本机多进程源码跑通（coordinator 用 subprocess 编排 kdc/relay/device）；阶段二三方向完成后 Docker+Web 联调（2026-08-17 决策）。
6. **代理签名保留（warrant 限定）**：中继真实签名任务=会话准入凭证签发（授权书限定范围，不能签新授权）；伪造边界=授权书范围。配合 NAT 穿越条件量化（D0）证明中继=真实必需基础设施（NAT 兜底），非人为引入。

### D0 组网基础设施（节点发现+拓扑构建）

- **实验**：协调服务设备注册/公告 + find_node 查询（DHT 简化替代）；中继维护邻居表构建星型拓扑；新设备"发现→入网→与已准入设备通信"全链路可行性证明。
- **NAT 穿越条件量化（中继必要性论证）**：①理论矩阵——NAT 类型对（全锥/受限锥/端口受限/对称）× 直连可行性，引 RFC 4787/5389/5766；②模拟打洞——设备加虚拟 NAT 层（类型可配），代表性类型对实测直连成功率；③兜底率推导——假设 NAT 类型分布，计算需中继兜底比例，并对比"直连 vs 走中继"时延/吞吐差。输出 `expB1_nat.csv`。论据链：**P2PVPN 无法无条件打洞 → 中继=真实必需基础设施（NAT 兜底）→ 代理委托（D2）与数据面兜底（D4）有理**。
- **简化声明（论文口径）**：以集中信令替代 DHT 实现节点发现，拓扑为星型；证明"分布式组网技术可支撑票据化准入"即可；NAT 穿越以理论矩阵+代表性模拟呈现（单机环境，对称 NAT 等难点如实标注）。
- **对比向**：内部机制验证（可行性）+ 方案引文（[17] TUN P2PVPN、[22] 国密 P2P VPN 的 DHT/信令参照）。
- **论文位置**：4.2（组网与拓扑）+ 4.5（实验）。

### D1 票据化准入有效拦截（实验 B1+B4）

- **实验**：6 类节点（合法/过期/重放/伪造/篡改/冒用）分类正确率（应 100%）；B4 七用例拦截率；与"无票据 P2PVPN"基线同用例拦截率对比（安全差距证据）。
- **联动用例（方向一）**：B1 新增"绑定校验"——设备入网须关联已认证用户（绑定表 user_bio_did↔device_did）；无绑定/绑定用户未认证 → 拒绝。"先认证用户，再授权设备"零信任联动。
- **对比向**：数值自实现（同环境无票据基线）；方案引文（[22][51] 现状参照）。
- **论文位置**：4.3（方案）+ 4.5（实验）+ 第6章安全属性矩阵。

### D2 授权委托安全（代理签名，warrant 限定）

- **机制**：KDC 生成授权 A={DID_dev, policy, exp, Sig} + 代理签名密钥分发中继，附**授权书（warrant）**限定"只能为通过三重验证的设备签发**会话准入凭证**（绑定 DID+NetPerm+有效期），不能签发新授权/新票据"；中继代理验签，并为准入设备签发会话准入凭证（数据面凭此快速放行，避免每包重验授权）。
- **实验**：中继代理验签；**伪造能力测试**——授权书范围外签发凭证 100% 无效（中继无 KDC 主密钥，无法伪造新授权/越权授权）。
- **对比向**：内部机制验证（伪造测试）；方案引文（SM9 高级原语 [12][13][14][15]；SM9 代理签名待检索）。
- **论文位置**：4.3（方案）+ 4.5（实验）。

### D5 SM9 密钥协商隧道（实验握手/吞吐 + B4-4）

- **实验**：SM9 密钥协商握手轮次/时延、隧道吞吐、中继侧仅见密文（B4-4 恶意中继）；vs **TLS 隧道基线（python ssl 自实现，同环境）**；IPsec 全栈自实现不现实，以文章定性+文献数值引用（IPsec 网关终止可解密 vs 本文中继不可解密）。
- **对比向**：数值自实现（TLS 自实现基线）+ 方案引文（中继不可解密 vs TLS/IPsec 网关终止，定性）。
- **论文位置**：4.4（方案）+ 4.5（实验）。

## 5. 方向三设计（C0-C4）

### 叙事定位（论文第 5 章主线）

MCP 安全"从无到有"：**无认证**（实测 40% 服务器裸奔）→ **OAuth 2.1**（授权态复用/粒度粗/撤销慢等隐患）→ **本文 SM9 票据化**。MCPS（IETF draft）/SMCP（arXiv:2602.01129）为同阶段密码学化共识，作三角佐证，定位"**互补非替代**"，不与首创之争纠缠。

**外网化论证（需求真实性六因）**：MCP 从内网 stdio 出身 → 远程化强制（OAuth 2025-03）→ 外网化必然——①网络效应 ②Agent 长尾能力 ③组织边界外数据 ④标准化降本 ⑤商业变现 ⑥用户即跨网 Agent。六因支撑"MCP 需要票据化安全"的需求真实。

### 开题承诺（逐条闭合）

① Agent 视为特殊设备节点，生成设备 DID 并关联 SM9 私钥；② KDC 签发内嵌组网权限的 ST 票据（ST_net），P2P 中继验证 SM9 授权及 ST 票据合法性后放行接入 P2PVPN；③ 用户生物 DID 关联 SM9 私钥，KDC 签发绑定数据/协同权限的 ST 票据（ST_data），MCP 服务端验证票据及权限匹配性；④ Agent 协同指令附加"用户生物DID签名 + Agent设备DID签名"SM9 签名链，携带双 ST；⑤ MCP 服务端校验签名链与 ST 有效性后转发，实现组网、数据、协同权限精准管控。

开题全文本对照：**14 个承诺点全部闭合（无缺口）**；2 处措辞对齐（Agent=特殊设备节点、中继验证写全"SM9 授权+ST+DID"）。

### Agent 身份锚点（"Agent=特殊设备节点"工程论证）

四类运行环境唯一标识：docker container id（64 hex）/ linux `/etc/machine-id`（32 hex）/ windows MachineGuid（36 字符）/ vmware UUID（36 字符）→ `make_device_did` 派生设备 DID。环境重建/克隆由"重注册+登记表"兜住。

### C0 Agent 身份锚点可行性

- **实验**：生成 4 类环境唯一标识 → `make_device_did` 派生 Agent 设备 DID → 唯一性/冲突重试；环境重建→新标识→重注册走登记表；克隆→相同标识→注册去重。
- **对比向**：内部机制验证（可行性）；把"Agent=特殊设备节点"从假设变成工程事实。
- **论文位置**：5.2（方案）论证 + 5.5（实验）。

### C1 分级授权功能（三场景）

- **实验**：场景 A 数据查询（用户授权 Agent 查库，ST_data 四步验证）、场景 B 协同任务（多 Agent 链式，每级双签名链+双 ST）、场景 C 跨域转发（经 mcp_gateway 验证 ST_net 访问异网 MCP）；审计 ticket_id 关联链贯通。
- **对比向**：内部功能验证（三场景跑通）。
- **论文位置**：5.3（方案）+ 5.5（实验）。

### C2 签名链性能（本文 vs OAuth 基线）

- **实验**：并发 100/500/1000 req/s；单请求验证时延 p50/p90/p99、QPS、消息尺寸开销；OAuth 基线同环境自实现。
- **对比向**：数值自实现（同环境 OAuth 2.1 授权码+PKCE）。
- **论文位置**：5.5（实验）。

### C3 指令攻击与正确性（三方案对比 + 消融）

- **实验**：≥500 条指令（正常 60%/篡改 16%/越权 16%/重放 8%），三方案（无管控/OAuth/本文）各跑一遍；C3-1~C3-6 攻击用例（见《代码汇总版》§5.4）；消融三档（全量/去用户签名层/去 ST_data）。
- **C3-6 调用者混淆**：忠实复刻 OAuth 现状"一次性授权后 server 级授权态缓存复用"缺陷，让攻击真打穿 OAuth 基线；本文每请求带认证器拦截。
- **对比向**：数值自实现（同环境 OAuth/无管控基线）+ MCPS/SMCP 佐证。
- **论文位置**：5.4（安全分析）+ 5.5（实验）。

### C4 安全属性对比矩阵

- **实验**：7 维（抗重放、抗伪造、权限粒度 tool 级、调用级绑定防调用者混淆、审计归因、撤销/生命周期、国产合规）× 4 方案（标准 Kerberos / 国密 Kerberos / OAuth 2.1 直连 / 本文）；定性+半定量（能实测填实测值，其余填依据）。
- **对比向**：方案引文（Kerberos 标准）+ 数值自实现（能实测的维度）。
- **论文位置**：5.5 + 第6章安全属性矩阵。

### 方向三文献

- MCPS（IETF draft）、SMCP（arXiv:2602.01129）——同阶段共识佐证；OAuth 2.1 规范（RFC 9700 及 2025-03 远程化强制）；MCP 无认证实测（40% 裸奔）出处待定稿；其余见八方向综述/文献库。

## 8. 票据存储与数据流转证明

- **存储**：TGT/ST 客户端缓存（ccache），KDC 无状态；撤销靠短 TTL（30min）+熔断+重签。
- **流转证明**：ticket_id 关联链——KDC 签发生成 ticket_id → 中继验证日志 → MCP 调用携带 → 审计记录（ts, ticket_id, 双DID, tool, 判定）。方案：A ticket_id 关联链（推荐）/ B 集中审计日志 / C 中继三重验证记录。

## 9. MCP 兼容（不改 MCP 协议）

| 方案 | 做法 | 兼容性 | 改动量 |
|---|---|---|---|
| A 网关层接入 | 中继做 MCP 网关，认证在网关层 | 零改动 | 中 |
| **B 头部注入（推荐）** | 请求附 ST（header `X-ST-Ticket`） | 报文不变 | 小 |
| C 服务端中间件 | 服务端前加验证中间件（验 ST+签名链） | 部署加层 | 小 |
| D OAuth 映射 | 认证映射 MCP OAuth（ST 等价 token） | 完全生态 | 大 |

推荐 **B+C**。调用链：Agent 指令（双 DID 签名）+ 双 ST（header）→ 中继验证 → MCP 中间件验 ST+签名链 → 权限匹配（claims_checker）→ 转发 → 审计（ticket_id）。
