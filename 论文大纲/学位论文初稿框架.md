# 学位论文初稿框架

## 题目（暂定）

**基于SM9与生物特征模糊提取的Kerberos身份认证及ST票据P2PVPN安全通信机制研究（面向MCP云服务）**

---

## 摘要（拟）

针对传统 Kerberos 协议票据伪造、静态密钥泄露、生物特征隐私保护不足，以及零信任环境下安全通道动态建立、MCP 云服务接入无票据管控等问题，本文研究 SM9 标识密码、生物特征模糊提取与 Kerberos/P2PVPN 的深度融合机制。首先利用生物特征模糊提取技术生成稳定生物密钥，构建去中心化生物 DID，由 KGC 在可信执行环境中派生 SM9 私钥，并以 SM9 数字签名重构 Kerberos AS-REQ 流程；其次设计基于 ST 票据的 P2PVPN 动态授权与安全通信机制，通过设备 DID、SM9 授权委托与代理签名实现组网准入控制，结合 SM9 密钥协商与特征流量整形构建安全隧道；最后面向 MCP 云服务提出设备与生物双 DID 结合 ST 票据的分级授权机制与双签名协同指令验证方案，实现组网、数据、协同权限的精准管控。安全性分析与实验验证表明，所提方案可有效阻断票据伪造与重放攻击路径，提升身份认证、安全通信与 MCP 服务交互的整体安全性。

**关键词：** SM9；Kerberos；生物特征模糊提取；P2PVPN；ST票据；MCP安全；身份认证

---

## 第1章 绪论

### 1.1 研究背景与意义

Kerberos 作为经典的第三方可信认证协议，通过 KDC 统一签发 TGT 与服务票据（ST）实现单点登录与双向认证，已在企业域环境、分布式系统中广泛应用。然而传统 Kerberos 以静态口令作为唯一凭据，存在口令被暴力破解、票据被伪造与重放、KDC 单点受攻击等固有风险[1][2][21]；同时随着零信任理念与物联网、车联网、云服务等场景的普及，海量异构设备与 AI Agent 的接入认证、动态授权与端到端安全通信成为新的安全需求，传统中心化认证与粗放权限管控模式难以满足。

国家密码管理局发布的 SM9 标识密码算法以用户标识直接作为公钥，免去证书管理，具备轻量、灵活的密钥管理优势，已进入 ISO/IEC 国际标准并广泛应用于政务、电力物联网等领域[33][40]。将 SM9 与生物特征、DID、Kerberos 票据体系结合，构建"生物特征绑定、标识密码支撑、票据动态授权"的身份认证与安全通信体系，对落实商用密码应用、推进零信任建设与保障 AI 云服务安全具有重要的理论意义与应用价值。

### 1.2 国内外研究现状

#### 1.2.1 Kerberos 协议安全研究现状

针对 Kerberos 的安全性缺陷，国内外学者从算法替换、协议扩展与去中心化三方面开展研究。Qatinah 等系统分析了 Kerberos 面临的重放攻击、票据伪造、口令猜测等攻击及其对策[1]；Chen 等提出去中心化 Kerberos 服务管理协议 DKSM，通过区块链消除 KDC 单点故障[2]；KESIC 扩展面向智能与物联网设备的 Kerberos 认证[3]；国内学者提出基于 HMAC 的消息认证改进[5]、基于国密算法的 Kerberos 身份认证协议改进[21][22]以及面向单点登录的改进协议[23]。总体来看，现有工作多停留在算法替换或架构调整层面，缺少将生物特征、标识密码与票据流程深度融合的认证重构。

#### 1.2.2 SM9 标识密码研究现状

SM9 自 2016 年发布以来，形成了数字签名、密钥交换、密钥封装与加密的完整算法体系[33]，相关研究涵盖盲签名[12]、环签名[13]、高效签密[14]、可撤销标识广播加密[15]等密码学扩展，以及政务、电力物联网、安全邮件等应用生态[40][41]。在身份认证方向，SM9 的标识即公钥特性与 KGC 密钥派生机制，为"以 DID 为标识、以生物密钥为派生输入"的认证体系提供了天然支撑，但将 SM9 私钥派生置于可信执行环境（TEE）并绑定生物 DID 的研究仍较少。

#### 1.2.3 生物特征模糊提取研究现状

Dodis 等首次提出模糊提取器（Fuzzy Extractor）概念，从含噪生物特征中提取均匀随机且可再生的密钥[35]；Boyen 提出可复用模糊提取器以抵抗多模板关联攻击[36]；Hao 等将模糊金库应用于虹膜实现密码与生物特征的结合[37]；Becker 分析了辅助数据操纵攻击下的鲁棒模糊提取器[38]。国内学者将模糊提取器应用于 PUF 芯片密钥重建[25]与多因素身份认证[16]，并利用生物特征模糊提取实现容错认证与匿名密钥协商[39]。上述研究表明，通过码生成辅助数据与多数投票等策略可从指纹、虹膜等含噪生物特征中稳定提取密钥，为生物密钥驱动 SM9 私钥派生奠定了技术基础。

#### 1.2.4 P2PVPN 与零信任研究现状

P2PVPN 以分布式组网替代中心化网关，消除传统 VPN 的中心化受攻击面与 DoS 风险[17][19]；基于国密算法的 P2P VPN 实现验证了国产密码在组网场景的可行性[22]；零信任理念强调"永不信任、持续验证"，基于零信任的 VPN 访问控制技术[51]与 ZTNA 架构已成为安全接入的主流方向，但动态授权票据与标识密码结合的 P2P 组网准入机制仍有研究空间。

#### 1.2.5 MCP 协议安全研究现状

Model Context Protocol（MCP）作为 AI Agent 连接工具与数据源的事实标准，其授权基于 OAuth 2.1/PKCE 且为可选实现，协议层不强制安全机制，导致凭证集中、权限过大、工具投毒与指令篡改等风险[45][46][50]。NSA 发布 MCP 安全设计指南，指出动态工具调用、隐式信任、令牌生命周期缺失等核心风险[45]；学术界揭示了 MCP 生态的寄生工具链攻击[43]、工具投毒[44]与提示注入漏洞[42]，CVE-2025-49596 亦暴露了未认证 MCP 实例的远程代码执行风险。面向 MCP 云服务引入票据化接入管控与签名链验证，是当前研究的前沿空白。

#### 1.2.6 Agent 身份管理研究现状

OpenID 基金会发布 Agentic AI 身份管理白皮书，指出传统 IAM 框架需演进以适应自主 AI Agent 的身份认证与授权需求[11]；云安全联盟提出基于 DID、可验证凭证与 ZKP 的 Agent IAM 新方法[47]；零信任 Agent 身份框架将 Agent 视为受治理的非人身份[48]；W3C DID 标准为去中心化标识提供了规范基础[49]。将设备 DID 与用户生物 DID 双身份模型嵌入票据授权体系的研究尚处起步阶段。

#### 1.2.7 研究现状述评

综上，Kerberos 票据体系、SM9 标识密码、生物特征模糊提取、P2PVPN 与 MCP 安全在各自领域均有成熟研究，但存在以下不足：一是 Kerberos 改进未与生物特征及标识密码深度融合，初始认证环节仍依赖静态凭据；二是 P2PVPN 组网缺少基于票据的动态授权与端到端身份管控；三是 MCP 云服务接入缺少票据化管控与多身份签名链验证机制。本文针对上述空白开展系统研究。

### 1.3 研究内容与研究目标

本文围绕"生物特征绑定身份、SM9 支撑密码、ST 票据管控授权"三层递进架构，开展三项核心研究：

1. **基于 SM9 与生物特征模糊提取的 Kerberos 身份认证方案**：研究生物密钥稳定生成、生物 DID 构建、KGC-TEE 私钥派生与 AS-REQ 签名重构，从初始环节阻断票据伪造与重放。
2. **基于 ST 票据的 P2PVPN 安全通信机制**：研究设备 DID 与 SM9 授权委托、P2P 中继代理签名验证、SM9 密钥协商与特征流量整形安全隧道，实现组网准入与端到端通信安全结合。
3. **面向 MCP 云服务的应用验证**：研究设备与生物双 DID 分级授权、Agent 协同指令签名链与 MCP 服务端验证流程，实现组网、数据、协同权限精准管控。

研究目标：提出一套安全性与效率可权衡的认证-组网-服务一体化安全机制，并通过原型系统与实验验证其可行性与性能优势。

### 1.4 论文组织结构

第1章介绍研究背景与国内外现状；第2章阐述相关技术基础；第3章至第5章分别对应三项核心研究内容；第6章给出实验方案与性能分析；第7章总结全文并展望后续工作。

## 第2章 相关技术基础

### 2.1 SM9 标识密码算法

SM9 是基于椭圆曲线对的标识密码算法，实体标识（如 ID、DID）直接作为公钥，私钥由 KGC 根据主密钥与标识计算生成，包含数字签名（GB/T 38635.2 规定的 KGC 签名、用户签名）、密钥协商与加密封装等算法[33]。其标识即公钥的特性免去证书管理与验证开销，密钥协商算法支持两实体直接建立会话密钥，适合海量设备与动态组网场景。

### 2.2 Kerberos 认证协议

Kerberos 基于可信第三方 KDC（含 AS 与 TGS）与票据体系，流程包括：客户端向 AS 提交身份请求获得 TGT；向 TGS 出示 TGT 换取服务票据 ST；向服务端出示 ST 与认证器完成认证[34]。票据包含时间戳与生命周期，认证器含时间戳与挑战值，用于防重放；协议依赖口令派生密钥，静态凭据是其安全短板[1]。

### 2.3 生物特征模糊提取技术

模糊提取器由生成算法 Gen 与再生算法 Rep 构成：Gen 输入一次生物采样 w，输出密钥 R 与辅助数据 P；Rep 输入另一含噪采样 w′ 与 P，在 w 与 w′ 距离足够近时恢复 R[35]。基于纠错码（如 BCH 码）构造的码生成方案将随机码字编码后与 w 异或生成 P，解码纠错实现密钥再生[37][25]；通过多次采集多数投票构成稳定比特序列，可进一步提升采样稳定性，同时辅助数据 P 不泄露生物特征与密钥信息，满足隐私保护要求[38]。

### 2.4 去中心化标识 DID

W3C DID 标准定义了基于 DID 文档的全球唯一标识与验证方法关联机制[49]。DID 由用户自主生成与控制，可绑定公钥、生物密钥摘要等验证材料，支持去中心化身份管理与跨域互操作，为生物密钥与设备标识的密码学绑定提供标准载体。

### 2.5 P2PVPN 组网技术

P2PVPN 通过 TUN/TAP 虚拟网卡与分布式路由表构建虚拟网络，节点间基于非对称加密建立点对点隧道，无需中心化网关，抗 DoS 能力与可扩展性优于传统 VPN[17]。组网涉及节点发现、NAT 穿越与拓扑构建，中继节点在不可直连场景下承担转发功能[19][22]。

### 2.6 MCP 协议与授权模型

MCP 采用客户端-服务器架构，通过工具、资源、提示三类能力暴露服务；授权基于 OAuth 2.1 与 PKCE，为可选实现[50]。协议层不强制安全机制，服务器承载多服务令牌，存在凭证集中、权限粒度粗、会话与令牌生命周期管理缺失等风险[45][46]，需在传输层之上的应用层补充身份认证与请求完整性保护。

## 第3章 基于SM9与生物特征模糊提取的Kerberos身份认证方案

### 3.1 问题分析

传统 Kerberos 初始认证以口令派生密钥加密会话密钥，攻击者可离线破解口令、重放 AS-REQ 流量；同时生物特征若以明文模板存储将面临泄露风险。本章目标：以生物密钥取代口令作为初始凭据，以 SM9 签名取代口令解密校验，重构 AS-REQ 流程。

### 3.2 方案总体设计

方案由用户端（生物采集与密钥生成模块）、KGC（TEE 私钥派生服务）与 Kerberos 认证体系（AS/TGS）构成。注册阶段完成生物密钥提取、生物 DID 生成与 SM9 私钥派生；认证阶段以"用户ID+生物DID+时间戳"的 SM9 签名消息发起 AS-REQ。

### 3.3 生物特征模糊提取与生物密钥生成

对用户指纹/虹膜等生物特征进行多次采样，经特征提取与量化构成比特序列；通过多数投票策略对多次采样的同位置比特取众数，消除不稳定位，形成稳定比特序列 w；采用码生成辅助数据方案：选取随机码字 c，计算辅助数据 P = w ⊕ Encode(c)，密钥 R = Hash(c)。认证时以新采样 w′ 计算 w′ ⊕ P 并经纠错解码恢复 c，进而再生 R[35][37]，实现含噪生物特征的密钥可靠恢复，同时 P 中不含生物特征明文信息。

### 3.4 生物DID生成与SM9私钥TEE派生

基于用户 ID 与生物密钥 R 的密码学摘要生成去中心化生物 DID（含用户 ID、密钥绑定验证材料与 DID 文档），由用户自主掌控。KGC 接收生物 DID 后，在可信执行环境（TEE）内完成身份核验与 SM9 签名私钥派生，主密钥与派生过程全程置于 TEE 内存隔离保护，防止主密钥泄露与恶意派生，私钥经安全信道下发用户端并绑定生物 DID 存储。

### 3.5 AS-REQ流程重构

将传统 AS-REQ 的口令校验替换为签名认证：客户端构造消息 M = {用户ID ‖ 生物DID ‖ 时间戳 ts ‖ nonce}，以 SM9 签名私钥生成数字签名 σ = SM9Sign(sk, M)，向 AS 发送 (M, σ, 生物DID)。AS 端校验：①时间戳新鲜性（|ts − t_now| < Δ，防重放）；②根据生物DID 查得对应 SM9 公钥并验证签名有效性（认证用户身份）；③校验生物DID 与用户 ID 绑定关系。验证通过后按原 Kerberos 流程签发 TGT 与后续 ST，实现"无口令、无票据伪造路径"的初始认证。

### 3.6 安全性分析

（1）抗口令攻击：初始凭据为生物密钥，无口令可破；（2）抗重放与票据伪造：签名绑定时间戳与 nonce，AS 拒绝过期与重复请求；票据仍受 TGT/ST 密钥保护，且攻击者无法伪造 SM9 签名；（3）生物隐私保护：仅保存辅助数据 P 与密钥摘要，生物模板不落库，P 不泄露生物信息；（4）KGC 安全：TEE 隔离使主密钥难以提取，私钥派生可审计。需注意生物特征熵有限，方案依赖模糊提取器的安全参数选择与 TEE 远程验证机制保证。

### 3.7 本章小结

本章方案实现生物特征、标识密码与 Kerberos 初始认证的深度融合，从源头上消除了口令凭据与初始票据伪造路径，为后续组网与服务授权提供可信身份基础。

## 第4章 基于ST票据的P2PVPN安全通信机制研究

### 4.1 问题分析

零信任环境下安全通道需按需动态建立；传统 VPN 中心化网关易受攻击、权限管控粗放。本章目标：以 ST 票据承载动态授权，借助 P2P 中继实现去中心化组网与准入控制，并以 SM9 密钥协商构建端到端安全隧道。

### 4.2 总体架构

系统由设备节点、KDC（授权签发方）、P2P 中继节点（代理签名者）与管理服务构成。设备基于唯一标识生成设备 DID 并关联 SM9 私钥；KDC 对"设备DID + 访问策略"签发 SM9 授权并委托给中继节点；P2P 网络负责节点发现与拓扑构建；中继节点验证授权与票据后提供通信中继；对等节点基于 SM9 密钥协商建立会话密钥，经特征流量整形构建安全隧道。

### 4.3 设备DID与SM9授权签发

设备出厂或入网时基于唯一标识（芯片序列号、硬件指纹等）生成设备 DID，KGC 派生设备 SM9 私钥并安全注入。原始授权方 KDC 针对设备 DID 及细粒度访问策略（可访问服务、带宽、时限）生成 SM9 授权凭据，并以代理签名形式委托给 P2P 中继节点，使中继节点无需知晓 KDC 主密钥即可代表其验证设备请求，实现授权与转发的解耦。

### 4.4 P2P组网与代理签名验证

设备加入网络时向中继节点提交设备 DID、SM9 授权与 ST 票据。中继节点执行三重验证：①验证 SM9 授权有效性（代理签名校验，确认授权真实且未过期）；②验证 ST 票据合法性（票据签名、时间戳与生命周期，防重放）；③校验设备 DID 一致性（请求签名者 DID 与票据、授权内 DID 一致，防冒用）。全部通过后为设备分配虚拟网络地址并建立转发规则，完成组网准入控制。

### 4.5 SM9密钥协商与特征流量整形安全隧道

对等设备间调用 SM9 密钥协商算法，以双方 DID 为标识公钥直接协商会话密钥，免去证书交换；会话密钥经 SM3/SM4 派生用于数据加密与完整性保护。基于带特征流量整形机制构建安全隧道：对隧道流量按协议特征进行整形与填充，隐藏流量统计特征，降低流量分析攻击风险，同时结合零信任"持续验证"原则周期性复核票据与授权状态。

### 4.6 安全性分析

（1）去中心化抗毁性：中继为无状态代理，KDC 离线不阻断既有会话，单点受攻击面显著缩小；（2）动态授权：ST 票据绑定设备 DID 与策略，细粒度、可撤销、可审计；（3）端到端安全：SM9 密钥协商保证会话密钥仅在两端建立，中继无法解密流量；（4）抗重放与冒用：时间戳、nonce 与 DID 一致性校验构成多重防护。性能开销主要为 SM9 双线性对运算与代理签名验证，可通过预计算与批量验证优化。

### 4.7 本章小结

本章方案以 ST 票据为授权载体，实现 P2PVPN 组网准入控制与端到端通信安全的结合，满足零信任环境动态授权与安全通道建立需求。

## 第5章 面向MCP云服务的应用验证

### 5.1 MCP云服务安全需求分析

MCP 云服务场景面临设备/Agent 接入无票据管控、数据权限与身份分离、协同指令易篡改等问题[45][46]。本章将第3章生物身份与第4章设备身份统一为双 DID 模型，构建分级授权与签名链验证机制。

### 5.2 设备与生物双DID分级授权机制

将 Agent 视为特殊设备节点：为 Agent 生成设备 DID 并关联 SM9 私钥，KDC 签发内嵌组网权限的 ST 票据，P2P 中继节点验证 SM9 授权与 ST 票据合法性后允许 Agent 接入 P2PVPN，完成组网权限管控；用户生物 DID 关联 SM9 私钥，KDC 签发绑定数据访问或协同权限的 ST 票据，由 MCP 服务端验证 ST 票据及权限匹配性后开放对应数据与工具能力，完成数据权限管控。两级授权互相独立、按需签发，实现最小权限原则。

### 5.3 Agent协同指令签名链与验证流程

Agent 发起协同指令时，指令附加"用户生物DID签名 + Agent设备DID签名"的 SM9 签名链，同时携带双 DID 对应的 ST 票据。MCP 服务端验证流程：①校验两张 ST 票据的合法性（签名、时效、权限范围）；②校验签名链有效性（指令未被篡改，且确由授权用户与合法 Agent 联合发起）；③校验签名者 DID 与票据内 DID 一致性；④完成权限与指令内容的匹配性检查后执行数据转发。任一步骤失败即拒绝执行，实现协同指令的完整性与来源可信。

### 5.4 应用验证场景设计

依托西安邮电大学无线网络安全技术国家工程实验室的网络安全测试环境与网络仿真平台，搭建 MCP 云服务原型：部署 KDC、TEE-KGC、P2P 中继节点与 MCP 服务器，接入模拟 Agent 与用户终端，验证设备接入准入、数据访问授权、协同指令转发三类场景的完整流程；同步开展 SM9 签名、模糊提取与隧道吞吐的性能测试，并与 OAuth 直连方案对比安全属性与开销（详见第6章）。

### 5.5 本章小结

本章将认证与组网机制落地到 MCP 云服务场景，通过双 DID 分级授权与签名链验证，实现组网、数据、协同权限的精准管控，验证了前两章方案的工程可行性。

## 第6章 实验方案与性能分析

### 6.1 实验环境

依托西安邮电大学无线网络安全技术国家工程实验室：含商用密码算法库（SM2/SM3/SM4/SM9）、可信执行环境（SGX 或 TEE 模拟平台）、KVM/容器化网络仿真平台与安全测试设备；开发语言采用 Go/Python，密码运算基于国家商用密码算法实现。

### 6.2 实验内容与评价指标

（1）**功能验证**：覆盖第3章注册-认证全流程、第4章入网-通信全流程、第5章三类 MCP 场景，用例包括重放、伪造票据、DID 冒用、指令篡改等攻击测试；（2）**性能测试**：测量模糊提取注册/再生时延、SM9 签名与验证时延、AS-REQ 认证时延、P2PVPN 隧道吞吐与握手开销，并与标准 Kerberos 及 OAuth 方案对比；（3）**安全性对比**：从抗重放、抗伪造、隐私保护、权限粒度、单点故障五个维度进行定性对比分析。

### 6.3 预期结果

预期方案在安全性指标上全面优于传统 Kerberos 与 OAuth 直连方案；性能上认证时延增加可控制在可接受范围（毫秒级），隧道吞吐损耗低于常规 VPN 方案；通过实验室仿真验证方案在物联网与 MCP 云服务场景的可行性与可部署性。

## 第7章 总结与展望

本文围绕"生物身份-标识密码-票据授权"主线，构建了从身份认证到安全组网再到云服务管控的一体化安全机制：第3章以生物模糊提取与 SM9 签名重构 Kerberos 初始认证，消除静态凭据与票据伪造路径；第4章以 ST 票据实现 P2PVPN 动态授权与端到端安全通信；第5章面向 MCP 云服务实现双 DID 分级授权与签名链验证。实验验证了方案的可行性与性能。

后续工作方向：（1）引入可复用模糊提取器与基于格的模糊提取方案[36][38]，提升生物密钥的安全性与多设备一致性；（2）研究跨域 Kerberos 联盟场景下的 ST 票据互认与撤销机制；（3）将签名链验证与可验证凭证（VC）、零知识证明结合，进一步强化 MCP 场景的隐私保护与最小授权；（4）开展真实生物特征库与大规模节点组网下的压力测试。
